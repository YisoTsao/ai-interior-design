# 11 前台需求規格書 v2：對標市面設計平台的功能缺口

版本：2.0｜日期：2026-09-30｜範圍：**只含前台畫面與互動**（不含資安、後端、帳務、基礎設施）
上層文件：[01-prd](01-prd.md)、[02-ux-spec](02-ux-spec.md)、[03-frontend-design](03-frontend-design.md)｜相關決策：ADR-017、021、023

---

## 0. 怎麼讀這份文件

- **目標**：讓 InteriorAI 的前台具備市面主流室內設計平台的完整功能面，並保留我們的差異化（可編輯 Scene Graph＋AI 渲染結構驗證＋物理光線）。
- **對標對象**（以公開功能為準，2026 年）：

  | 類型 | 產品 | 我們主要參考的強項 |
  |---|---|---|
  | 專業雲端設計 | 酷家樂 Coohom、Homestyler（美間）、Foyr Neo | 硬裝（鋪磚、吊頂、牆面造型）、訂製櫃、施工圖、雲端渲染、全景、報價 |
  | 大眾家居規劃 | Planner 5D、RoomSketcher、Floorplanner、HomeByMe、Sweet Home 3D | 上手快的 2D/3D、範本、大型家具庫、樓層、分享 |
  | 建築／進階建模 | SketchUp、Live Home 3D | 自由建模、剖面、日照、測量、圖層、群組 |
  | 行動與掃描 | Magicplan、IKEA Kreativ／Place | 手機量測、LiDAR 掃描成平面圖、AR 擺放、清空房間 |
  | AI 設計工具 | Interior AI、RoomGPT、Spacely AI、Collov AI | 照片一鍵換風格、局部重繪、虛擬家具佈置、風格探索 |

- **狀態符號**：✅ 已有｜🟡 部分／簡化版｜❌ 尚無
- **優先級**：**P0** 缺了就不像一個設計平台（對標基本盤）｜**P1** 主流平台普遍具備｜**P2** 進階或差異化
- 每條需求以 `FE-<模組>-<序號>` 編號，驗收標準寫成可以用 E2E 或人工檢查驗證的句子。

## 3. 遊戲化介面規範（延續 ADR-023）

1. **版面**：頂列（專案層級）／左建造面板（工具快捷列＋資產物品欄＋清單）／中央視埠（浮動 HUD）／右屬性面板（分節）／底狀態列。任何新功能先決定歸屬區域，不新增第五個常駐區。
2. **視覺語言**：深色半透明面板、斜切角、金色＝主要／選取、青色＝數值與互動回饋、分類色條＝資產類型。狀態回饋一律有光暈或色條，不只換文字。
3. **數值控制**：連續值用滑桿＋數值輸入（放開提交）；色彩用取色器＋恢復預設；開關用 switch；所有覆寫都能一鍵恢復預設。
4. **物理讀數**：燈具與材質顯示真實單位（lm、cd、lx、K、W、mm），讓設計與施工一致。
5. **可及性**：所有 HUD 控制有 aria-label、鍵盤可達，對比 ≥ 4.5:1；axe 無 serious/critical（E2E 已涵蓋）。

## 5. 共通驗收條件（所有 FE 需求）

1. 持久變更一律經 Command，可 undo/redo，並寫入 Scene（ADR-001）；純 UI 狀態不入 Scene。
2. 新增欄位遵守 schema 版本規則：選填、附 migration 與 Golden File 測試。
3. zh-TW／en 文案同步；無硬編碼 UI 字串（eslint i18next 規則）。
4. 2D 與 3D 呈現同一份資料；任何一邊修改，另一邊即時一致。
5. 中階筆電：2D 5,000 圖元 60 FPS、3D 互動 ≥ 50 FPS、首次可互動 ≤ 3 秒（B8）。
6. 每個新畫面至少一個 E2E 流程測試＋一次 axe 檢查；畫布操作提供清單或面板的等價路徑。
