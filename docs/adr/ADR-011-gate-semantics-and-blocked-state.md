# ADR-011 Gate 判定與受阻處理
狀態：接受
日期：2026-09-29
背景：原規格未定義「指標未達標」與「需要人決策」時 Gate 是否通過，也未定義受阻後怎麼走。
決策：
1. **Gate 通過**＝該 Phase 指令退出碼皆為 0 ＋ 產出物齊全（`check_gates.py`）＋ 規定的量測**已記錄**於 PROGRESS。
2. **硬性 Gate（未達即不通過）**：正確性與安全類——帳本併發/冪等、遮罩外像素逐位元不變、尺度未知不得回最終 Scene、助理零次未確認修改、DXF 尺寸誤差 ≤1%、授權欄位缺失不得 published。
3. **軟性指標（記錄即通過，未達標列為發佈阻擋項）**：效能預算（B8）、AI 結構驗證通過率、CV 的 IoU/F1、資產件數。未達標必須寫入 PROGRESS「未達標清單」並建立改善 Task，P8 的 release-checklist 逐項處理。禁止調低門檻掩蓋。
4. **受阻（⚠）**：需要金鑰、付費、法務或人決策而無法繼續某項時，用 mock/骨架完成能完成的部分，在 PROGRESS 標 ⚠ 並寫明「解除條件」；繼續做**不依賴它**的 Phase。P8 前必須把所有 ⚠ 轉成 release-checklist 的「未驗證/需人決策」。
5. mock 通過≠真實供應商通過；凡由 mock 驗證的門檻一律標「未校準」。
後果：check_gates 會讀取 PROGRESS 的 ⚠ 與「未達標清單」。
