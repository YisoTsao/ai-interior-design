# ADR-022 P5 平面圖辨識的實作決策
狀態：接受
日期：2026-09-30

決策：
1. **cv-service 同步解析**：`POST /v1/parse` 直接回 PlanResult；非同步（Job、進度、重試、失敗處理）由 Node 的 `plan_import` 任務包裝（06 §1 允許）。
   cv-service 422＝業務失敗（不重試）；連線錯誤/5xx 交給 BullMQ 重試。平面圖匯入免費（不扣點）。
2. **向量優先**：DXF 以 ezdxf 解析（圖層啟發式、雙線牆配對、門弧/窗線補缺口、端點吸附）；`$INSUNITS` 缺失＝尺度未知（不猜）。
   DWG 與 PDF 目前**拒絕**（授權/沙箱與 PDF 向量抽取列入後續）。合成 DXF 牆長誤差 0.000%。
3. **點陣：傳統 CV＋可替換分割介面**（`Segmenter`：傳統 CV 預設；`SEG_MODEL_PATH` 提供 ONNX 權重時使用）。沒有使用任何第三方資料集/預訓練模型。
   門窗改以「符號偵測」（門：牆外細線元件＝門扇＋1/4 弧、外框約正方形且一邊貼在牆缺口；窗：牆缺口中的細長元件），
   偵測到的缺口先補回牆 mask 再向量化；外框上的外牆段最後合併（外牆封閉）。
4. **尺度**：尺寸標註 OCR（Tesseract：數字＋附近平行的細尺寸線 → mm/px，多個估計取中位數）；讀不到＝unknown，
   只以門寬中位數給 `suggestedMmPerPx` 建議值（不套用）。**校正 UI 一律要求使用者確認或兩點校正**（掃描件 OCR 可能誤讀）。
5. **VLM 只補語意**：`VisionProvider` 介面＋確定性 mock（OCR 文字正規化；否則依面積啟發式），只寫 `label/labelSource`，幾何不動。
   真實 VisionProvider 未核對（models.yaml vision: TODO-verify）→ 未驗證。
6. **匯入 Scene**：`importPlan` Command（app-state）直接建立牆與開口（不做共線合併以免開口 offset 失效）、不合法者略過並回報、
   房間由牆自動偵測並以落在房內的文字命名；前端先做直角吸附與接點修補（端點投影到鄰牆中心線）。單一 undo 步驟。
7. **評測與回歸**：合成資料（BSP 戶型 × 5 繪圖風格）＋ `eval/run.py`（分風格報告、`eval/baseline.json`，主要指標退步即失敗；CI python job 執行）。

量測（20 張/風格、held-out）：門窗 F1 0.973、牆 IoU 0.724、房間 IoU 0.493、尺度自動判定 70–100%（中位誤差 0.3%；掃描件 17%）。
〔假設〕目標：牆 IoU ≥ 0.80 **未達標**；門窗 F1 ≥ 0.85 達標（僅限合成資料）。真實圖面（建照圖/DM/手繪/掃描）準確率**未驗證**。
